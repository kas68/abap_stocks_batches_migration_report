*******************************************************************************
* HBM : Batch Stock Transfer to New Plant (Split Valuation)
* Program version: v0.6 (storage-location mapping table ZPTP_SLOC_MAP);
*                  names follow the Sysmex D-Project ABAP Development
*                  Standards & Naming Conventions v1.2
* DDIC objects to create in SE11 BEFORE activating ZPTP_SPLIT_VAL_MIG
* Work Stream ID: PTP (MM, Appendix B of the standard)
* Package (suggested): ZPTP_SPLIT_VAL  (Z<WS_ID>_<name>)
********************************************************************************
* Log tables:
*   - ZPTP_MOV_EXEC  : one line per processed record / 301 attempt
*   - ZPTP_BATCH_EXT : one line per batch handled in the target plant (created,
*                    already existing, simulated or failed)
* Both client-dependent, delivery class A, Display/Maintenance allowed.
* Mapping table:
*   - ZPTP_SLOC_MAP  : source plant + storage location -> target plant +
*                    storage location, read by the program            [v0.6]
********************************************************************************

================================================================================
DOMAINS / DATA ELEMENTS
================================================================================
Reuse standard: MATNR, CHARG_D, WERKS_D, LGORT_D, BWTAR_D, BWKEY, XCHPF,
MENGE_D, MEINS, BWART, BUDAT, MBLNR, MJAHR, SYMSGID, SYMSGNO, SYMSGTY,
ERNAM, ERDAT, ERZET.
NUMC06 (NUMC 6, used by POSNR): create it if it does not exist in the system.

Custom (naming: data element ZDE<name>, domain Z<name>):
Data element ZDELOT_RUN_ID   Domain CHAR32     Migration run id (base)
Data element ZDELOT_RUN_SEQ  Domain NUMC3      Restart sequence (001,002,...)
Data element ZDELOT_RUN_MODE Domain ZLOT_RUN_MODE (CHAR1)
   Fixed values: F = Full Validation Mode
                 D = Direct Transfer Mode
Data element ZDELOT_STATUS   Domain ZLOT_STATUS (CHAR1)
   Fixed values: S = Success / posted
                 E = Error / blocked / excluded
                 W = Warning
                 T = Test / Simulation (not posted)
                 Z = Zero quantity - no movement
                 X = Skipped (reconciliation / not processed)
                 I = Inconsistent (SAP stock not in input file, segment exists)

================================================================================
TABLE  ZPTP_SLOC_MAP   "Storage location mapping for the migration     [v0.6]
================================================================================
Delivery class C            Data maintenance: Display/Maintenance Allowed
Field         Key  Element / Type       Description
--------------------------------------------------------------------------------
MANDT          X   MANDT                 Client
WERKS_SRC      X   WERKS_D               Source plant (8P01)
LGORT_SRC      X   LGORT_D               Source (issuing) storage location
WERKS_DST      X   WERKS_D               Target plant (8Q01)
LGORT_DST          LGORT_D               Target (receiving) storage location

Technical: buffering off, size category 0.
Foreign keys (check table T001L): WERKS_SRC + LGORT_SRC, WERKS_DST + LGORT_DST.
Maintenance: generate the table maintenance dialog (SE54, authorization group
other than &NC&, "Log Data Changes" on) and maintain it with SM30. Delivery
class C: entries are transported with customizing requests.

The program reads the entries WHERE WERKS_SRC = P_WSRC AND WERKS_DST = P_WDST.
Every issuing storage location holding stock in the source plant needs an
entry; a missing one blocks the line (024). Several source storage locations
may map to the same target storage location.

Example:
  WERKS_SRC  LGORT_SRC  WERKS_DST  LGORT_DST
  8P01       0001       8Q01       0001
  8P01       0002       8Q01       0001
  8P01       QA01       8Q01       0100

================================================================================
MESSAGE CLASS  ZPTP_SPLIT_VAL  (SE91) - used by the program
================================================================================
002  Zero quantity in input file - no movement created
003  Valuation type &1 not created in target plant &2
004  Quantity mismatch: file &1 vs SAP &2 (variance &3)
005  Cannot allocate &1 &2 to storage locations of plant &3 (&4 available)
006  No unrestricted stock in plant &1 for material &2 batch &3
007  Line &1: quantity &2 is not numeric - line rejected
008  Line &1: negative quantity &2 - line rejected
009  Line &1: layout error (field count / mandatory field) - line rejected
010  Inconsistency: SAP stock not in input file but valuation segment exists
011  SAP stock not in input file (no target segment) - not processed
012  &1 input line(s): batch column normalised to blank (placeholder value,
     or material not batch-managed)
013  Material &1 is batch-managed in plant &2 but the input line declares NO_BATCH
014  Material &1 is not extended to plant &2
015  Material &1 declares NO_BATCH but holds unrestricted batch stock in
     plant &2 (MCHB)
016  Batch &1 of material &2 split over several valuation types - batch
     rejected (one valuation type per batch)                        [v0.3]
017  Line &1: unit of measure &2 unknown - line rejected            [v0.3]
018  Unit &1 differs from base unit &2 of material &3               [v0.3]
019  Batch &1 exists in plant &2 with valuation type &3, file gives &4
                                                                    [v0.3]
020  Source batch &1 cannot be read in plant &2                     [v0.3]
022  Update failed after commit - document &1 not posted            [v0.3]
023  Storage location &1 does not exist in plant &2 - line not
     transferred                                                    [v0.4]
024  No mapping for storage location &1 of plant &2 to plant &3 in
     ZPTP_SLOC_MAP - line not transferred                           [v0.6]
025  Material &1 is managed with split valuation in plant &2 - not
     eligible for the non split valuation option                    [v0.7]
026  Material &1: batch management differs between plant &2 and
     plant &3                                                       [v0.7]
(The program passes MSGID/MSGNO together with a free text in MSGTX; the entries
 above are required so MSGID/MSGNO resolve to a text when the log is reported on.
 009 is also used when the material number cannot be converted (MATN1).
 Errors returned by BAPI_BATCH_CREATE / BAPI_GOODSMVT_CREATE keep the BAPI's own
 message class and number.)
Standard 4.10: a dedicated message class per large development (hence
ZPTP_SPLIT_VAL, not a shared ZPTP), numbered placeholders &1..&4, no 000/999,
long text (problem / what to do / admin) to be maintained for each entry.

================================================================================
DDIC STANDARDS TO APPLY WHEN CREATING THE OBJECTS (standard sec. 4.19)
================================================================================
- Both tables as column store.
- Lock object EZPTP_MOV_EXEC (E<database table>) if the log is updated by
  more than one program; the report itself runs one RUN_ID at a time.
- If an SM30 maintenance view is generated: "Log Data Changes" on and an
  authorization group other than &NC&. As the log is the audit trail,
  display-only maintenance is preferred.
- Transaction code, if one is needed: ZPTP_SPLIT_VAL_MIG (Z<WS_ID>_<name>).
